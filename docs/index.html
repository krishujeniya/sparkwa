The Headless WhatsApp Bridge for Google Gemini Spark

Connect your personal WhatsApp directly to your autonomous Google Gemini Spark agent via event-driven Gmail triggers. Runs as a single native Go binary on any 512 MB Linux server with zero runtime dependencies.

Zero Privacy Leaks

System Integration Pipeline

SparkWA is designed with total privacy abstraction. The terminal user interface (TUI) and system logs never reveal your phone numbers, emails, or message bodies. Instead, actions are tracked through a deterministic 4-node flow.

NODE [1]

WhatsApp Bot

Dedicated secondary WhatsApp SIM account. Connects headlessly via terminal QR code.

NODE [2]

Authorized User

Your personal WhatsApp number. Only this number is permitted. Strangers are rejected.

NODE [E]

Gmail Bridge

Secure Google Cloud OAuth 2.0 mailbox on VPS that delivers commands to Gemini Spark.

NODE [S]

Gemini Spark

Your autonomous AI agent in Google Workspace with direct access to Docs, Drive & Calendar.

DATA PIPELINE: [2 ➔ 1] Inbound ➔ [1 ➔ E] Bridge Dispatch ➔ [E ➔ S] Spark Process ➔ [S ➔ E] Spark Reply ➔ [E ➔ 2] WhatsApp Delivery

24/7 Autonomous Execution

Master Gemini Spark System Prompt

Copy and paste this exact instruction into your Gemini Custom Instructions, Gem instructions, or Scheduled Task. It gives Spark permanent standing authorization so it never pauses to ask "Should I send this email?", never echoes command envelopes, and always delivers the direct answer to your WhatsApp.

GEMINI SPARK MASTER INSTRUCTION 
You are an autonomous execution worker integrated with SparkWA. You run 24/7 in the background without requiring manual human supervision.

You receive automated tasks via incoming emails with subjects formatted as:
[SPARKWA:REQUEST_ID] <Short Title>

The email body will follow this format:
BEGIN SPARKWA COMMAND
Request ID: <REQUEST_ID>
Authorized sender: <MASKED_PHONE>
Timestamp: <ISO8601>
Command: <USER_INSTRUCTION>
END SPARKWA COMMAND

OPERATING PROTOCOL:
1. IMMEDIATE AUTONOMOUS EXECUTION (24/7):
   - You have standing, permanent authorization to execute tasks and send reply emails automatically.
   - NEVER ask "Should I send this email?", "Do you want me to reply?", or "Shall I proceed?".
   - NEVER pause or wait for user confirmation to send the email response. Send the email reply directly and immediately to the sender.

2. NEVER ECHO OR QUOTE THE INPUT:
   - NEVER repeat, quote, or echo the "BEGIN SPARKWA COMMAND" block in your reply.
   - Extract only the text after "Command: " and treat it as the real instruction to execute.
   - If the command is a conversational greeting (e.g., "Hi", "Hello"), reply directly and politely.
   - If the command is a query, answer it thoroughly.
   - If the command requires Google Workspace tools (Gmail, Drive, Docs, Sheets, Calendar), use them directly to complete the task.

3. STRICT RESPONSE FORMAT:
   Always reply directly to the email thread using this exact structure:

BEGIN SPARKWA RESPONSE
Request ID: <REQUEST_ID>
Status: SUCCESS
Result: <YOUR DIRECT ANSWER, SUMMARY, OR OUTPUT>
END SPARKWA RESPONSE

   - Replace <REQUEST_ID> with the exact Request ID from the incoming email.
   - Put your actual answer or output after "Result: ".
   - Do not include extra conversational text outside of this block.

4. SAFETY GUARDRAILS (DESTRUCTIVE ACTIONS ONLY):
   - Only if a command asks for an irreversible or high-risk action (such as deleting files, mass-emailing clients, or financial transactions), do NOT execute it immediately.
   - Instead, respond with:

BEGIN SPARKWA RESPONSE
Request ID: <REQUEST_ID>
Status: APPROVAL_REQUIRED
Result: This action requires your confirmation: [brief description]. Reply YES to confirm.
END SPARKWA RESPONSE

Step-by-Step

5-Minute Server Deployment

Complete walkthrough to deploy SparkWA to any clean Ubuntu 24.04, 22.04, or Debian VPS.

1

Install via Single Command

Run the automated installer on your server to install SparkWA and create system services:

curl -fsSL https://raw.githubusercontent.com/krishujeniya/sparkwa/main/scripts/setup-apt.sh | sudo bash
2

Download Google OAuth Credentials

In Google Cloud Console, create an OAuth Client ID (Desktop App) with Gmail API enabled, download the JSON file, and save it as /etc/sparkwa/credentials.json:

sudo chmod 0600 /etc/sparkwa/credentials.json
3

Configure via Guided Setup Wizard

Launch the interactive control menu and select [1] Guided Setup Wizard:

sudo sparkwa

Enter your Bot WhatsApp number (+country code), your personal phone number, and your Gmail accounts.

4

Pair WhatsApp via Terminal QR Code

From the control menu, select [2] Pair WhatsApp. Open WhatsApp on Phone Number 1, go to Linked Devices > Link a Device, and scan the terminal QR code.

5

Enable Background Systemd Service

Start the persistent daemon so SparkWA runs 24/7 across server reboots:

sudo systemctl enable --now sparkwa

Enterprise Hardening

Security & Privacy Architecture

SparkWA is engineered for fail-closed, multi-tenant safety. Your server is completely isolated.

[SHIELD] Strict Allowlist Only

SparkWA enforces strict fail-closed phone authorization. Messages from unauthorized phone numbers, group chats, broadcasts, or bots are dropped immediately with zero execution.

[LOCK] Zero Shell Execution

SparkWA contains zero shell evaluation (no sh -c or exec.Command on user input). All tasks are purely routed via structured Google API requests.

[BOX] Systemd Linux Sandboxing

Runs under strict Linux sandboxing: ProtectSystem=strict, ProtectHome=yes, NoNewPrivileges=yes, and PrivateTmp=yes.

[EYE] Total Privacy Masking

Phone numbers, email addresses, and command contents are scrubbed from TUI screens and daemon logs, preventing unauthorized shoulder-surfing on shared VPS terminals.

Answers

Frequently Asked Questions

Do I need to leave my laptop on?

No. SparkWA runs 24/7 in the background on your Linux VPS (or Raspberry Pi). Your laptop can be closed or turned off.

Does SparkWA require Docker, Node.js, Python, or Chromium?

No. SparkWA is written in pure Go and compiled into a single static binary. It has zero external software dependencies.

How much RAM does it need?

SparkWA uses approximately 28 MB to 35 MB of RAM at idle. It runs reliably on the smallest 512 MB or 1 GB VPS instances.

What happens if my VPS reboots?

The systemd service unit automatically starts SparkWA on boot, reconnects WhatsApp and Gmail, and recovers any pending tasks from the embedded SQLite database.
